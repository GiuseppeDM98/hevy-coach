> repo-wide rules; domain narratives go to `doc/guide/<tema>.md` as they are born (a stub stays

## 1. What this repo is
A single-user, self-hosted coach on top of Hevy and the Anthropic API (CLAUDE.md § Project
Overview). The v1 is built one spec at a time from `doc/v1/` (index `00-INDICE.md`): a spec is the
only instruction of a session; what it does not say is asked to the owner, never decided alone.

## 2. Repo-wide conventions

### 2.1 Layers and imports
`src/app` (routes, route handlers, Server Actions) is thin: parse with zod, call a use case, map the
result. `src/lib/review`, `src/lib/sync`, `src/lib/apply`, `src/lib/plan`, `src/lib/progress` hold
the use cases and the pure domain. `src/lib/db/repositories/*` is the only place that writes SQL
(Drizzle); `src/lib/hevy/*` the only place that talks to Hevy; `src/lib/review/model.ts` the only
file importing `@anthropic-ai/sdk`; `src/lib/push/send.ts` the only file importing `web-push`.
Pure modules never import `next/*`, the DB client or `fetch`, and take `now: number` as a parameter.
The app reaches external services through `src/lib/container.ts` (`getDb`, `getHevyClient`,
`getReviewModel`; fakes under `E2E_FAKE_SERVICES=1`); CLI scripts in `scripts/` build the clients
directly. Rules: DEVELOPMENT_GUIDELINES.md § Code Structure.

### 2.2 Naming
Files kebab-case; functions verb + noun (`syncWorkouts`, `buildRoutineBody`); booleans `is/has/can`;
DB tables and columns snake_case, TypeScript camelCase (Drizzle maps them). The series labels
(`D-12`, `T-3`, `C-7`, «spec 04») never appear in code, comments or commit messages: write the why
in full. Plan identifiers are stable contracts: `RoutineKey` (`mon_upper_a` …), `SlotId`
(`mon_push_up` …), `VariantId` (`decline_push_up` …), `ScaleId` (`push_up` …).

### 2.3 Secrets and the owner's data
Secrets only in `.env.local` (gitignored) and in Vercel; `.env.example` lists every variable with an
empty value; `src/lib/env-schema.ts` is the zod schema, `src/lib/env.ts` the server-only instance.
Nothing of the owner's data in a tracked file, commit or PR: no real routine/workout id, no name, no
family detail (WORKFLOW.md § 1.6, public repo, no exception). Fixtures are sanitised as
`tests/fixtures/hevy/README.md` says; test numbers are invented and round.

### 2.4 Comments
Follow COMMENTS.md: a design comment at the top of a module that makes a non-obvious choice, a why
comment where the code looks wrong on purpose (the retry, the `batch` instead of a transaction, the
lower bound in `duration_seconds`), no TODO without an issue, no commented-out code.

### 2.5 Time
Instants are epoch ms UTC in the DB and in memory; calendar logic (days between, day start, next
Saturday) goes through `src/lib/time.ts` in `Europe/Rome`, never through `ms / 86400000` (the
2026-10-25 DST change makes a 25-hour day). Tests run with `TZ=Europe/Rome`.

## 3. Hevy (public API, OpenAPI 0.0.1 read 2026-10-23; the real payloads are in `tests/fixtures/hevy/`)
- Header `api-key` (a UUID), Pro account required. Do not call exactly at xx:00 (Hevy's request).
- `pageSize` maximum: **10** for `routines`, `routine_folders`, `workouts`, `workouts/events`;
  **100** for `exercise_templates`. Above it: 400 «pageSize must be less than or equal to 10».
- Single-object GETs (`/v1/workouts/{id}`, `/v1/exercise_templates/{id}`) return the bare object;
  routine POST/PUT/GET are declared `{ routine }` by the spec and the client accepts both shapes
  (spec 02's verification records which one is real).
- `PUT /v1/routines/{id}` **replaces the whole routine**: always GET, modify, PUT everything.
  **No DELETE** for routines, folders or exercise templates. `POST /v1/routines` → 403 «Routine
  limit exceeded» above Hevy's limit.
- Custom exercise templates can only be created (`POST /v1/exercise_templates` → `{ id }`, a UUID
  string for custom ones; catalog ids are 8 hex characters like `392887AA`). A custom template is
  for ever: find by **exact title** first, create only what is missing (`ensureTemplates`).
- Routine sets: `type` (`warmup|normal|failure|dropset`), `reps`, `rep_range {start,end}`,
  `duration_seconds`, all nullable; no AMRAP flag: «max-2», «per gamba», «45–60"» live in the
  exercise `notes`, generated by `targetNote` and never hand-written.
- `GET /v1/exercise_history/{templateId}?start_date&end_date` is not paginated;
  `GET /v1/workouts/events?since` gives `updated` / `deleted` events newest first.
- Rate limit: undocumented, no limit headers seen; the client retries once after 2 s on 429/5xx.
- Webhook (hevy.com → Settings → Developer → Webhooks): POST `{ "workoutId" }` with the user's own
  authorization header value; 200 within 5 s.

## 4. Plan data *(from spec 02 — stub; the full guide is `doc/guide/piano.md`)*
`src/lib/plan/plan.ts` (the five routines, their slots) and `src/lib/plan/scales.ts` (the scales of
variants, easiest first) are **data and contracts with Hevy**: a catalog id or a custom title changed
there creates a duplicate on Hevy. Every variant declares `quiet: true, simple: true` (no jumps, no
impacts, no technique). Targets: `reps` range, `max2` threshold, `hold` seconds/max seconds.
Snapshot tests fix the generated notes; `estimateRoutineMinutes` keeps every routine ≤ 40 min.

## 5. Database *(from spec 03 — stub; guide `doc/guide/sync.md`)*
Turso/libSQL through `@libsql/client` (Node entry; `file:local.db` in development, `:memory:` in
tests) and Drizzle. Schema changes only through `pnpm db:generate` + a committed migration in
`drizzle/`; never `drizzle-kit push`. `PRAGMA foreign_keys = ON` from the client. Multi-statement
writes use `db.batch([...])`, not interactive transactions (5 s lock on Turso). Production migrations
run from the owner's machine before the deploy that needs them.

## 6. Claude *(from spec 04 — stub; guide `doc/guide/revisione.md`)*
Model and prices in `src/lib/review/pricing.ts` (`claude-opus-5-5`, 4 / 20 USD per MTok). One call
per review through `client.messages.parse` with `max_tokens` and `output_config: { effort: 'high',
format: zodOutputFormat(…) }` explicit, no prefill, no forced `tool_choice`; the parsed output is
re-validated against the domain
(every eligible slot once, allowed actions, `next_variant` only with a successor); one retry on a
validation error; `refusal` / `max_tokens` → review `failed`, a refusal with its category
(`model: refusal (bio)`). The review has one deadline inside Vercel's 300 s: each call's timeout and
SDK retries come from the time left, a retry starts only with a minute to spare, and past the
deadline the review is `failed` with `model: timeout`, never left `running`. The variant scales are data: Claude
never names an exercise outside them.

## 7. Auth and app *(from spec 05a — stub; guide `doc/guide/app.md`)*
One identity: `APP_PASSWORD` compared in constant time, a signed JWT in the `hc_session` cookie for
365 days. `src/proxy.ts` is the first barrier, not the only one: every route handler calls
`sessionDenied()` and every Server Action `assertSession()` (a test greps for it). The only list of
public paths is `isPublicPath` in `src/lib/auth/session.ts`. UI in Italian, tokens from DESIGN.md,
no literal colours in components, Recharts only through `src/components/charts/recharts.ts`.

## 8. Deploy and PWA *(from specs 06 and 07 — stubs; guides `doc/guide/deploy.md`, `doc/guide/pwa.md`)*
Vercel Hobby, region `dub1`, production = `main`, no preview deployments; cron `17 6 * * 6` UTC with
`CRON_SECRET` (daily at most, ±59 min, duplicates possible, no retry, 1-hour logs → `cron_runs` in
the DB). Serwist service worker, `next build --webpack`, the SW only on production builds; Web Push
with VAPID, iOS only from the Home Screen, a notification always shown on `push`.

## 9. Testing
- Unit tests next to the module (`*.test.ts`), AAA, names as sentences. Every pure module has one.
- Repositories and use cases against an in-memory libSQL with the **real migrations**
  (`createMemoryDb()` from spec 03).
- Hevy and Anthropic are never called in tests: `fakeFetch` + fixtures (spec 01), fake model (04),
  in-memory fakes behind the container for Playwright (05a).
- Every test in a spec names the mutation that proves it load-bearing; a test that cannot go red is
  not a test.
- Playwright: `mobile` (390) and `desktop` projects on a seeded `e2e.db`; `pwa` project on a
  production build (07).

## 11. Gotchas (measured; add the date to every new one)
- 2026-10-23 — Turso has no Frankfurt region: Dublin (`aws-eu-west-1`) and Vercel `dub1`.
- 2026-10-23 — Vercel Hobby functions run up to 300 s (default and maximum); a 60–120 s Claude call
  fits without configuration, but `maxDuration` is still declared on the long routes.
- 2026-10-23 — Vercel's Deployment Protection on production would put the Vercel login in front of
  the phone PWA and (undocumented) the cron: production stays open with the app's own login.
- 2026-10-23 — Next 16: `middleware.ts` is `proxy.ts` (Node only); `cookies()` is async;
  `@serwist/next` needs `next build --webpack`; `cacheComponents` is opt-in and not used.
- 2026-10-23 — `web-push` 3.6.7 has had no release since 2024-01 but the repo is active and the
  Next.js docs still use it; never use `https://localhost` as the VAPID subject (Safari `BadJwtToken`).
- 2026-10-23 — Windows checkouts: keep LF (`.gitattributes`), or Biome goes red on files nobody
  touched (segnaprezzi, 2026).
